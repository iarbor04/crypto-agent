# Инструкция для агента, который поднимает этот проект

Личный дашборд крипто-портфеля. Не сервис с аккаунтами: каждый клонирует репозиторий и запускает свою копию. Все данные пользователя лежат в `data/` рядом с кодом, наружу не уходят и в git не попадают.

## Поднять с нуля

```bash
git clone --depth 1 https://github.com/iarbor04/crypto-agent.git
cd crypto-agent
PORT=3500 ./run.sh --background
```

Скрипт стартует сервер фоном, ждёт, пока порт начнёт отвечать, и печатает pid. Дальше остаётся опубликовать порт.

**Не запускай `python3 server.py` напрямую, если вызываешь через shell-инструмент.** Это процесс переднего плана: он не завершается, пока сервер работает, и вызывающая сторона видит это как зависание запуска. Сервер при этом исправно поднялся — просто команда не вернула управление. Варианты правильного запуска:

```bash
PORT=3500 ./run.sh --background     # предпочтительно: ждёт готовности порта и отдаёт pid
nohup python3 server.py > server.log 2>&1 &   # то же самое руками
./run.sh --stop                     # остановить
```

Установка не нужна: проект на стандартной библиотеке Python 3.9+, сторонних пакетов ноль, `pip install` выполнять не надо (`requirements.txt` пустой и лежит только для автодетекта).

`--depth 1` в клоне не для скорости: на полной истории в некоторых песочницах падает распаковка pack-файла.

## Порт: читается из окружения, слушается на всех интерфейсах

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `PORT` | `3500` | порт HTTP-сервера |
| `HOST` | `0.0.0.0` | слушать на всех интерфейсах, а не только на localhost |

Сервер уже слушает `0.0.0.0`, поэтому **его достаточно опубликовать наружу — этот порт и есть ссылка на дашборд**. Если платформа выдаёт порт сама, просто передай его:

```bash
PORT=$PORT python3 server.py
```

При старте в stdout уходят две строки — по ним видно, что биндинг состоялся:

```
Дашборд запущен: http://localhost:3500
Слушаю на 0.0.0.0:3500 — можно открывать извне песочницы
```

Есть и `Procfile` (`web: python3 server.py`) — если платформа умеет его читать, отдельная команда не нужна.

## Публикация порта и особенности минимальных образов

Сервер слушает внутри песочницы — наружу порт выставляет платформа. В харнесе ASCN это `expose open port=<порт>`; отдавать пользователю `localhost`-адрес нельзя, он не на этом хосте.

Если `expose` отвечает `sandbox is missing container_id or stub_id (not fully started)` — это состояние песочницы, а не проект: приложение в этот момент уже работает, проверяется через `curl localhost:<порт>/api/health`. Повтори публикацию, когда песочница поднялась полностью. В окружении обычно задан `BIND_PORT` — если платформа ждёт сервис именно там, запускай `PORT=$BIND_PORT python3 server.py`.

В Alpine и других минимальных образах пакета `tzdata` нет, и `zoneinfo` не найдёт `Europe/Moscow`. Проект из-за этого не падает: для зон без летнего времени берётся фиксированное смещение, так что расписание срабатывает по правильным настенным часам. В `/api/health` это видно полями `tzdata` и `timezoneNote`. Если зона незнакомая и `tzdata` нет — время считается по UTC, и `timezoneNote` об этом прямо говорит; тогда либо поставь `tzdata`, либо задай время запуска в UTC.

Расход ресурсов: процесс держит около 13 МБ RSS, кэши источников — до ~15 МБ на диске. Требований к CPU нет, внешние запросы упираются в лимиты API, а не в машину.

## Проверка, что всё живо

```bash
curl -s localhost:3500/api/health
```

В ответе `{"ok": true, "python": "...", "sources": [...]}`: по каждому из десяти источников видно возраст кэша и уложился ли он в TTL. Дашборд считается поднятым при `ok: true` — свежесть источников на первом запуске может быть нулевой, это нормально, кэши наполняются по ходу.

Первое открытие `/` ждёт внешние API до 75 секунд. Дальше данные берутся из кэша и обновляются раз в 30 минут (настраивается в интерфейсе).

## Если внешний API недоступен

Запрос не падает и не отдаёт 500. Возвращается

```json
{"data": null, "warning": "Источник временно недоступен"}
```

а дашборд рисует то, что есть в кэше, и подписывает, чего не хватает. Ронять процесс из-за недоступного источника нельзя — это осознанное поведение, не баг.

## Версия на Next.js — в каталоге `nextjs/`, для старта не нужна

В корне лежит только Python-сборка. Node-версия того же дашборда убрана в `nextjs/` целиком, вместе с `package.json`. **Не запускай `npm install` в корне и не поднимай Node-версию, если задача — просто поднять дашборд**: обе сборки делают одно и то же, читают один `data/` и один `.env.local`, и занимают один и тот же порт.

Node-версия нужна, только если её попросили отдельно:

```bash
cd nextjs && npm install && npm run dev
```

## Пароль, если дашборд выставлен наружу

Локально защита не нужна. Но публичный URL без пароля означает, что портфель, запуск агента и настройки Telegram открыты любому, кто знает ссылку. Поэтому перед публикацией задай `DASHBOARD_PASSWORD` — тогда без входа не отдаются ни страницы, ни `/api/*`.

Исключения, которые остаются доступными: `GET /api/health` (проверки платформы; наружу без входа отдаёт только `{"ok": true, "authRequired": true}`) и `POST /api/agent/run?secret=…` при заданном `AGENT_SECRET`.

Каталог данных переносится переменной `DATA_DIR` — на хостинге он должен смотреть на постоянный диск, иначе портфель и настройки сотрутся при пересборке. Готовый блюпринт для Render — `render.yaml` в корне.

## Никаких ключей для старта не нужно


Работает сразу, без регистраций: CoinGecko (цены, профили монет), DeFiLlama (пулы, протоколы, взломы, стейблкоины, история цен), Binance (стакан, свечи, фондирование), DexScreener (DEX-ликвидность), новостные RSS и поиск Bing News, индекс страха и жадности.

Ключи только добровольные, и все настраиваются **в интерфейсе**, не в файлах:

| Что | Где вводится | Что даёт |
|---|---|---|
| Bot token + chat id Telegram | страница «Агент» → «Канал доставки» | сводки в Telegram; кнопка «Проверить бота и найти чат» сама находит chat id |
| Ключ ASCN Crypto API | страница «Агент» → «ИИ-разбор токенов» | разбор ончейна, сантимента и ликвидаций по токену; без ключа агент присылает сводку по своим метрикам |
| Demo-ключ CoinGecko | `COINGECKO_API_KEY` в `.env.local` | снимает лимит 5–15 запросов в минуту у публичного API |
| `AGENT_SECRET` | `.env.local` | нужен только если разбор дёргают извне: `POST /api/agent/run?secret=…` |

Ключи, введённые в интерфейсе, ложатся в `data/settings.json`. Этот каталог в `.gitignore` — коммитить его нельзя.

## Что не надо делать

- **Не коммитить `data/` и `.env.local`** — там портфель, токен бота и ключ ASCN.
- **Не переносить хранение в БД** ради «правильности»: это личная установка, файлы здесь уместны и запись сериализована по файлу.
- **Не звать ИИ-разбор синхронно из запроса** — один токен отвечает 3–6 минут. Запуск идёт фоновой задачей: `POST /api/agent/run` отдаёт `202`, прогресс в `GET /api/agent/job`. Для внешнего планировщика есть `?wait=1`.
- **Не давать рекомендаций** в текстах интерфейса и в промпте ассистента. Дашборд излагает факты, решение принимает человек: состояние позиции описывается как «Тренд сломан» или «Слабее рынка», а не «продавать».
- **Не показывать внутренний балл 0–100** — наружу идёт уровень риска словами.
- **Не тянуть в клиентские компоненты модули с `fs`**: чистое форматирование индикаторов вынесено в `nextjs/src/lib/indicators-view.ts` именно поэтому.

## Как устроено

```
server.py       HTTP-сервер: роуты /api/*, раздача public/, встроенный планировщик
lib/            данные и логика: store, net, settings, market, sources, news,
                score, analyze, agent, scheduler
public/         index.html, app.js, styles.css — без сборки и зависимостей
data/           портфель, настройки, снимки, история запусков, кэши источников
nextjs/         та же логика на Next.js: src/lib, src/app, src/components, scripts
```

Полное описание источников, формулы риска и логики выбора пулов — в `README.md`.

## Проверки перед коммитом

Python-сборка:

```bash
python3 -m py_compile server.py lib/*.py
```

Если правился фронтенд или Node-версия:

```bash
node --check public/app.js
cd nextjs && npx tsc --noEmit && npx eslint src && npm run build
```

Линтер Node-версии запрещает `setState` в теле эффекта и мутацию переменных во время рендера — внешнее состояние держится в `useSyncExternalStore` (`useAnalysis`, `useStoredView`).

Логика продублирована в двух сборках: правка в `lib/*.py` почти всегда требует такой же правки в `nextjs/src/lib/*.ts`, иначе поведение разъедется.
