# ASCN.AI Portfolio — стейкинг, риски и агент

Дашборд по крипто-портфелю: где стейкать каждый токен и под сколько, какие токены слабые и что с ними делать, плюс агент, который дважды в день присылает в Telegram только изменения.

В корне — сборка на чистом Python без зависимостей, в `nextjs/` — та же логика на Next.js. Дизайн-система — та же, что в дашбордах продажника и рассылки (`ascn-broadcast-dashboard`): светлая тема, `--blue #4d5ff6`, сайдбар 248px, `metric-card`, Geist + lucide-react.

Каждый запускает свою копию у себя: это не сервис с аккаунтами, а личный дашборд. Портфель, настройки и кэши лежат в `data/` рядом с кодом и никуда не уходят.

Автоматическому агенту, который поднимает проект, — `AGENTS.md`.

## Запуск без Node — версия на чистом Python

В проекте две равноправные сборки одного дашборда. Если в среде нет Node, npm и Docker — берите эту: нужен только `python3` (3.9 или новее), внешних пакетов ноль, сборки нет.

```bash
git clone <репозиторий> && cd crypto-agent
cp .env.example .env.local     # необязательно: без ключей всё работает
python3 server.py
```

Или одной командой — `./run.sh` (сам найдёт python3 и создаст `.env.local`, если его нет). Фоном, с ожиданием готовности порта и записью в `server.log`:

```bash
./run.sh --background     # остановить: ./run.sh --stop
```

Фоновый режим нужен, если запуск идёт из скрипта или автоматики: обычный `python3 server.py` держит терминал занятым, пока сервер работает, и вызывающая сторона принимает это за зависание.

Сервер слушает `0.0.0.0:3500`, то есть открывается и извне песочницы. Порт меняется переменной `PORT`:

```bash
PORT=8080 python3 server.py
```

Что внутри:

| Файл | Что делает |
| --- | --- |
| `server.py` | HTTP-сервер на `http.server`, роуты `/api/*`, раздача `public/`, встроенный планировщик |
| `lib/` | те же модули, что в TypeScript-версии: цены, пулы, ликвидность, индикаторы, новости, риск, агент |
| `public/` | `index.html`, `app.js`, `styles.css` — без сборки, без зависимостей |
| `data/` | создаётся сама: портфель, настройки, кэши. В git не попадает |

Обе сборки читают один и тот же `.env.local` и один и тот же `data/`, поэтому портфель и настройки переносятся между ними без конвертации.

Проверка, что всё поднялось:

```bash
curl -s localhost:3500/api/health | python3 -m json.tool
```

Если наружу вообще не пускают (частый случай в песочницах), это определяется одной короткой пробой, и дальше источники не ждут своих таймаутов: разбор портфеля возвращается за секунды на кэше, а в `/api/health` поле `egress` показывает, что доступа нет и почему. Если внешний API недоступен, сервер не падает и не отдаёт 500 — в ответе приходит `{"data": null, "warning": "Источник временно недоступен"}`, а дашборд рисует то, что есть в кэше, и подписывает, чего не хватает.

## Пароль и вынос наружу

На своей машине пароль не нужен: пусто в `DASHBOARD_PASSWORD` — защиты нет. Но как только дашборд доступен снаружи, пароль обязателен: иначе любой, кто знает ссылку, видит портфель и может запускать агента и менять настройки Telegram.

```bash
openssl rand -base64 18          # сгодится как пароль
# в .env.local:
DASHBOARD_PASSWORD=<то, что получилось>
```

Как это работает: без сессионной куки не отдаются ни страницы, ни `/api/*` — только страница входа и её стили. Кука подписана HMAC-секретом, который лежит в `data/session-key.json` и переживает перезапуск, живёт 30 дней, помечена `HttpOnly` и `SameSite=Lax`, а за https добавляется `Secure`. Пароль сверяется постоянным по времени сравнением, после пяти промахов адрес отдыхает минуту. Открытыми остаются два маршрута: `/api/health` (чтобы проходили проверки платформы — наружу он отдаёт только `{"ok": true}`) и `POST /api/agent/run?secret=…`, если задан `AGENT_SECRET`, — внешнему планировщику пароль ни к чему.

## Развёртывание на публичный хост

Проект на голом Python без зависимостей, поэтому поднимается почти где угодно. Требования к площадке: `python3`, переменная `PORT`, постоянный диск (иначе портфель и настройки сотрутся при перезапуске) и режим «не засыпать» — иначе агент проспит расписание.

В репозитории есть `render.yaml`: в Render это Dashboard → New → Blueprint → выбрать репозиторий. Он поднимет сервис с `python3 server.py`, примонтирует диск в `/var/data`, подставит `DATA_DIR=/var/data` и спросит секреты (`DASHBOARD_PASSWORD`, токен бота, ключ ASCN) — в репозиторий они не попадают.

Каталог данных задаётся переменной `DATA_DIR` — на хостинге он должен указывать на смонтированный диск, иначе файлы затрутся при следующей сборке:

```bash
DATA_DIR=/var/data python3 server.py
```

Бесплатные тарифы обычно засыпают без трафика и не дают постоянного диска: дашборд открываться будет, но портфель придётся заводить заново после каждого простоя, а сводки в Telegram придут не по расписанию. Для настоящей работы нужен самый дешёвый постоянный тариф с диском.

## Запуск на Node (версия на Next.js)

Лежит целиком в каталоге `nextjs/`, в корне репозитория её файлов нет. Нужен Node 20.9 или новее.

```bash
git clone <репозиторий> && cd crypto-agent
cp .env.example .env.local
cd nextjs && npm install && npm run dev
```

Открыть http://localhost:3500 — портфель пустой, добавить токены через «＋ Мои токены» (поиск по тикеру или названию, количество вводится либо в токенах, либо сразу суммой в долларах — переключатель в поле) или нажать «Посмотреть на демо-портфеле». **Ни одного ключа для этого не нужно**: цены, доходности, ликвидность и новости берутся из публичных API.

Полезное после клонирования:

```bash
cd nextjs && npm run warm     # прогреть кэши, чтобы первое открытие не ждало внешние API
cd nextjs && npm run health   # что подтянулось, что просрочено, чего нет в конфиге
```

### Docker

```bash
cp .env.example .env.local
cd nextjs
docker compose up -d --build              # дашборд на http://localhost:3500
docker compose --profile cron up -d       # плюс агент: разбор в 9:00 и 21:00
```

Каталог `data/` смонтирован как том — портфель и настройки переживают пересборку образа. Порт меняется переменной `HOST_PORT`.

### Что задаётся в `.env.local`

```
TELEGRAM_BOT_TOKEN=   # @BotFather → /newbot
TELEGRAM_CHAT_ID=     # @канал (бота добавить админом) или id чата
AGENT_SECRET=         # защита cron-эндпоинта
COINGECKO_API_KEY=    # рекомендуется: бесплатный demo-ключ, 30 запросов/мин
```

Ничего из этого не обязательно: без Telegram агент просто скажет, что канал не настроен, без ключа CoinGecko будет работать на публичных лимитах.

**Про лимиты CoinGecko.** Публичный API без ключа держит ~5–15 запросов в минуту, а один разбор портфеля из 5 токенов делает ~11 запросов (цены, поиск тикеров, профили монет). Все запросы идут через очередь с паузой и повтором на 429, профили кэшируются на 24 часа — но при первом холодном запуске часть профилей может подтянуться только со второй попытки. Бесплатный demo-ключ (coingecko.com → Developers → Demo API key) снимает проблему полностью.

**Ключ ASCN тоже вставляется в дашборде** — страница «Агент» → «ИИ-разбор токенов» → поле «API-ключ ASCN», рядом кнопка «Проверить ключ» (задаёт ассистенту короткий вопрос и показывает, за сколько секунд он ответил). Ключ ложится в `data/settings.json`, наружу отдаётся только маска. Если поле пустое, берётся `ASCN_API_KEY` из `.env.local`.

Telegram настраивается на странице «Агент», без правки файлов (настройки лягут в `data/settings.json`):

1. `@BotFather` → `/newbot` → скопировать токен, вставить в поле **BOT TOKEN**;
2. написать своему боту `/start` в личку (или добавить его админом в канал и что-нибудь туда отправить);
3. нажать **«Проверить бота и найти чат»** — дашборд спросит у Telegram, кто боту писал, и подставит `chat id` сам;
4. **«Сохранить»**, затем **«Тест сообщения»** — должно прийти в Telegram.

## ИИ-разбор токенов (ASCN Crypto API)

Кроме своих метрик агент отдаёт важные токены ИИ-ассистенту ASCN и получает то, что публичные API не дают: ончейн-потоки, поведение крупных адресов, свежие новости и кластеры ликвидаций.

По каждому токену уходит контекст, который дашборд уже посчитал (позиция и доля, динамика 24ч/7д/30д/год, просадка от хая, ёмкость выхода и DEX-ликвидность, плата за плечо, доступный стейкинг, взломы, технические индикаторы, оценка риска с причинами), и просьба разобрать четыре раздела с конкретными числами, адресами, уровнями и датами:

1. **технический анализ** — дивергенции, сжатие волатильности, объёмный профиль, уровни с ценами, структура тренда;
2. **ончейн** — потоки на биржи против обычного, крупные адреса и смарт-мани, доля свежих кошельков, концентрация у топ-холдеров, CEX против DEX;
3. **сантимент** — внимание и настроение, сила против BTC/ETH и сектора, открытый интерес и базис, новости последних 24–48 часов с датами;
4. **ликвидации** — сколько ликвидировано за сутки по лонгам и шортам, кластеры с ценами и объёмами, фондирование, уровень запуска каскада.

В конце ассистент даёт два списка фактов — **что за позицию** и **что против**, каждый пункт с числом. Они парсятся, складываются в `data/ai-insights.json` и **показываются прямо в карточках** рядом с причинами из моей модели.

**Рекомендаций дашборд не даёт.** Промпт запрещает «стоит продать» и «целесообразно сократить»: ассистент излагает факты и их следствия, решение принимает человек. По той же причине состояние позиции описывается фактом — «Тренд сломан», «Слабее рынка», «В рамках рынка», — а не приказом.

Ответ конвертируется в Telegram-HTML и уходит отдельным сообщением на каждый токен.

```
POST https://b2b.api.ascn.ai/api/ai-assistant/v2/invoke_assistant
X-API-Key: <ASCN_API_KEY>     модель ascn_v1.2, auto_hil: true
```

**Один разбор токена идёт 3–6 минут** (замеры: 174 и 197 секунд). Из этого следуют три решения в коде:

- запуск разбора — **фоновая задача**: `POST /api/agent/run` отвечает `202` за миллисекунды, прогресс читается из `GET /api/agent/job`, интерфейс показывает «ИИ-анализ токенов: 1 из 2». Для внешнего планировщика есть `?wait=1`, которым пользуется `scripts/run-agent.mjs`;
- запросы по токенам уходят **параллельно**, поэтому два токена — это те же 3–4 минуты, а не восемь;
- ИИ вызывается **только по важным токенам**: смена вердикта, health ±12, движение цены ±12%, свежие плохие или хорошие новости, депег, вердикт «продавать» или «сокращать». Если важного нет, запросов не будет вообще. Сколько токенов брать за прогон (1–5) выбирается на странице «Агент», по умолчанию 3.

Без `ASCN_API_KEY` агент работает как раньше — сводка по своим метрикам, без ончейна и ликвидаций.

Тикеры не уникальны: по запросу `APE` есть и ApeCoin, и Ape and Pepe с более высоким рангом — поэтому точное совпадение тикера всегда идёт первым, а выбранный `coinId` сохраняется в портфеле.

## Как считается риск позиции

Наружу дашборд показывает **уровень риска словами** — низкий, умеренный, повышенный, высокий, критический — и полосу, которая заполняется вместе с риском. Абстрактных «health 36/100» в интерфейсе нет: число 0–100 осталось внутри, для сортировки, порогов и контекста для ИИ.

Восемь блоков, каждый даёт свой вклад — на вкладке «Разбор» видно, из чего собрался уровень:

| Блок | Вес | Смысл |
|---|---|---|
| Динамика против рынка (7д, 30д) | 25 | падает ли токен сильнее BTC/ETH — это про токен, а не про рынок |
| Абсолютный тренд 30 дней | 10 | направление цены |
| Структурный тренд (200д, 1г) относительно рынка | 15 | долгое отставание — не просадка, а история |
| Ликвидность выхода | 10 | реальная глубина стакана Binance + DEX-пулов против размера **вашей** позиции; прокси «объём / капитализация» только если стакана нет |
| Новостной фон | 18 | тон заголовков по ключевым словам, от −3 до +3 |
| Просадка от максимума + давность хая | 12 | −99% пять лет назад ≠ −99% в этом году |
| Разлоки (в обороте / всего) | 8 | сколько сапплая ещё придёт в рынок |
| Есть ли надёжный стейкинг | 2 | актив без доходности лежит мёртвым грузом |

Уровни: **низкий** от 72, **умеренный** 56–71, **повышенный** 42–55, **высокий** 28–41, **критический** ниже 28.

Плюс жёсткие правила, которые перебивают математику:

- **критичная новость** (взлом, скам, делистинг, закрытие проекта, депег, остановка выводов) → балл ≤ 22 и вердикт «продавать»;
- **структурно сломанный актив** (≤ −95% от хая, минус за год, минус за 200 дней) → балл ≤ 36;
- **обвал за сутки** ≥ 15% → −10;
- **взлом самого проекта** за последние 2 года → −4, а если вынесли больше $10M → −7.

Вердикты рядом с риском: критический — продавать, высокий — сокращать, повышенный — наблюдать, умеренный — держать, низкий — держать и стейкать.

Подписи в интерфейсе намеренно без жаргона: не «TVL», а «в пуле»; не «impermanent loss», а «цены могут разъехаться»; не «ёмкость выхода», а «сколько можно продать сразу»; не «фондирование перпа», а «плата за плечо». Термины, которые аудитория знает (APY как «% в год», спред), оставлены, но с пояснением в подсказке.

## Как выбирается «куда поставить»

Верхний вариант — не максимальный APY, а устойчивый:

- спот-ставка подрезается средней за 30 дней (`apyMean30d × 1.3`) и ограничивается сверху — 500% в тонком пуле не должны выигрывать у Lido;
- риск 1–5 считается по TVL, impermanent loss, доле наградных токенов, флагу `outlier` и категории протокола;
- LP получает штраф: это другой продукт — нужен второй актив и есть IL;
- история взломов протокола повышает риск соразмерно инциденту: вынос от $10M — это +2, утечка на $300K — только пометка в карточке;
- по каждому пулу доступна история ставки за полгода с медианой и диапазоном за 90 дней, плюс комиссии протокола за 30 дней — видно, зарабатывает он на пользователях или живёт на эмиссии;
- в заголовок («поставить под X%») попадает только **однотокенный** вариант с риском ≤3, TVL ≥ $1M и APY ≥ 1%. Если такого нет — так и написано: «надёжного варианта нет», а агрессивные пулы показаны отдельным блоком.

Из этого же считается KPI «Потенциал стейкинга» — по надёжным вариантам, а не по самым жирным.

## Агент и расписание

Агент сравнивает текущий разбор со снимком прошлого запуска (`data/last-snapshot.json`) и отправляет только дельту: смену вердикта, изменение health на 12+, движение цены на 12%+, новые плохие и хорошие новости, рост ставок стейкинга на 3+ п.п. Если важного нет — молчит (переключается галочкой «присылать сводку всегда»).

**Расписание задаётся в интерфейсе, crontab не нужен.** На странице «Агент» — выключатель, время запусков (сколько угодно, до восьми), пресеты «утро и вечер / три раза / каждые 6 часов» и галочка «догонять пропущенное». Часовой пояс определяется автоматически. Планировщик живёт внутри приложения (`src/instrumentation.ts` → `src/lib/scheduler.ts`), проверяет время каждые 30 секунд и помечает сработавшие слоты в `data/schedule-state.json`, чтобы не запускаться дважды за день. Если машина спала — при следующем старте пропущенный запуск догонится.

Единственное условие: дашборд должен быть запущен. Для постоянной работы — `docker compose up -d` или `npm run build && npm start` под systemd/launchd.

Если планировщик приложения не подходит (например, дашборд поднимается по требованию), разбор можно дёргать снаружи. У cron минимальный `PATH`, поэтому путь к node — абсолютный (`which node`), а вывод стоит писать в лог:

```
0 9 * * *  cd "/path/to/crypto-agent" && /usr/local/bin/node scripts/run-agent.mjs >> "/path/to/crypto-agent/data/agent-cron.log" 2>&1
0 21 * * * cd "/path/to/crypto-agent" && /usr/local/bin/node scripts/run-agent.mjs >> "/path/to/crypto-agent/data/agent-cron.log" 2>&1
```

Дашборд при этом всё равно должен быть запущен — скрипт дёргает его по HTTP. На macOS каталог `~/Documents` защищён: если лог не появляется, дайте `/usr/sbin/cron` доступ в System Settings → Privacy & Security → Full Disk Access.

Или из любого планировщика:

```
curl -X POST "http://localhost:3500/api/agent/run?secret=$AGENT_SECRET"
```

## Хранение и надёжность

Файловое, без БД: `data/portfolio.json`, `settings.json`, `last-snapshot.json`, `agent-runs.json` (последние 60) и кэши источников. Запись сериализована по файлу с уникальным `.tmp`, чтобы параллельные апдейты не теряли данные. Битый или отсутствующий файл кэша не ломает работу — читается как «нет данных».

Что сделано, чтобы дашборд не падал на чужой машине:

- **у каждого источника свой лимит времени**, а у всего разбора — общий дедлайн 55 секунд. Что не успело — отмечается в `warnings`, страница показывает жёлтый баннер «данные неполные» и работает на остальном;
- **ни один источник не критичен**: нет цен — токен покажется без метрик; нет пулов — не будет доходностей; нет новостей — скор посчитается по цене, ликвидности и разлокам;
- **источник упал, а кэш есть** — отдаётся последнее удачное значение вместо ошибки;
- **пустой портфель** — валидный сценарий: страница открывается, ничего не считается, предлагается добавить токены;
- **`/api/health`** отдаёт конфигурацию и свежесть каждого кэша (`npm run health`);
- **свежая установка не содержит чужих позиций** — демо-портфель подгружается только по кнопке.

Интерфейс на русском. Полноценная локализация (английский, китайский, арабский с направлением справа налево, португальский) отложена осознанно: словарь на пять языков — это ~1800 строк и 92 КБ, но основная стоимость не в нём, а в переписывании 368 русских фрагментов в компонентах и 265 в серверных текстах (причины оценки, алерты, сводка для Telegram). ## Ограничения

- Портфель вводится руками; подключения кошелька по адресу пока нет.
- Тикеры разрешаются автоматически (точное совпадение + лучший market cap rank); если подставилась не та монета — выбрать нужную в «Мои токены» → «не тот токен?».
- Дашборд не знает, что уже застейкано: «потенциал» считается со всей позиции.
- Ёмкость выхода для DEX — оценка: сдвиг цены v2-пула на 1% принят за 0.25% его TVL, для concentrated liquidity это консервативно.
- График за 30/90/365 дней — это текущие позиции по историческим ценам, а не реальная история сделок (о чём подписано под графиком).
- Новостной тон — по ключевым словам в заголовках и анонсах (RU/EN), не LLM. Ошибается на иронии и заголовках-вопросах.
- **Общие ленты пишут в основном про топ-10**: в 326 материалах из 13 источников за сутки «ApeCoin» и «Arbitrum» не встретились ни разу. Поэтому по каждому токену дополнительно запрашивается RSS-выдача поиска Bing News с фильтром «за последний месяц» — она даёт настоящие заголовки вроде «Arbitrum Jumps 19% as Robinhood Chain Trading Volume Hits $568M». Google News RSS сознательно не используется: его условия разрешают только персональные читалки, а выдача забита конвертерами валют и страницами с ценами.
- **В оценку идут только новости не старше 14 дней.** Поиск любит поднимать статьи трёхлетней давности, и без этого фильтра эксплойт ApeCoin 2022 года обрушал сегодняшнюю оценку до критической. Старые материалы всё равно показываются в дровере — с датой и пометкой «в оценку не идёт».
- Гарантированного покрытия по совсем мелким токенам всё равно нет: там новости приносит ИИ-разбор, и вкладка «Новости» при пустых лентах показывает его новостной раздел. Платные API с поиском по монете (CryptoCompare, NewsAPI, CryptoPanic Pro) требуют ключа, GDELT по мелким токенам пуст, Reddit RSS отдаёт 403.
- Не инвестиционная рекомендация: это калькулятор публичных данных.
