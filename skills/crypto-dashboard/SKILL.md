# Навык: поднять дашборд портфеля и опубликовать ссылку

Навык для агента в песочнице ASCN. Задача: поднять веб-дашборд из репозитория `iarbor04/crypto-agent` и выдать пользователю публичный URL.

## Порядок действий

### 1. Код

```sh
cd /data/workspace
[ -d crypto-agent ] && (cd crypto-agent && git pull) || git clone --depth 1 https://github.com/iarbor04/crypto-agent.git
```

`--depth 1` обязателен: на полной истории в песочнице падает распаковка pack-файла. Если `git pull` ругается на повреждённый объект — удали каталог и клонируй заново.

Устанавливать нечего: проект на стандартной библиотеке Python 3, сторонних пакетов ноль. `pip install` не запускать, `npm install` не запускать (Node-версия лежит в `nextjs/` и не нужна).

### 2. Порт

Возьми порт, который платформа уже прошила под публикацию:

```sh
echo "BIND_PORT=$BIND_PORT STUB_ID=$STUB_ID STUB_TYPE=$STUB_TYPE"
```

Если `BIND_PORT` задан — поднимай сервис **на нём**, а не на 3500. Публикация чужого порта может не пройти, если платформа регистрирует только прошитый.

### 3. Запуск

```sh
cd /data/workspace/crypto-agent
PORT="${BIND_PORT:-3500}" ./run.sh --background
```

**Не запускай `python3 server.py` напрямую.** Это процесс переднего плана: он не завершается, пока сервер работает, shell-инструмент ждёт его вечно, и это выглядит как зависание запуска, хотя сервер поднялся. `run.sh --background` стартует фоном, сам ждёт готовности порта и печатает pid.

Остановить: `./run.sh --stop`. Лог: `server.log` в корне проекта.

### 4. Проверка до публикации

```sh
curl -s "localhost:${BIND_PORT:-3500}/api/health"
```

Смотри три поля:

- `"ok": true` — сервер жив.
- `"egress"` — пускают ли из песочницы наружу. Если `false`, дашборд откроется и будет работать, но цены, пулы и новости будут пустыми: данные берутся из публичных API, взять их больше негде. Это ограничение сети песочницы, а не дефект проекта — сообщи причину из `reason` как есть.
- `"tzdata"` — если `false`, время расписания считается по фиксированному смещению. Для Alpine это норма.

Если порт не ответил — приложи последние строки `server.log`, не угадывай причину.

### 5. Публикация

Сначала посмотри, что уже опубликовано, потом открывай:

```
expose list
expose open port=<порт из шага 2>
```

Если `expose` отвечает `sandbox is missing container_id or stub_id (not fully started)`:

1. Повтори через 5–10 секунд: песочница могла ещё не зарегистрироваться.
2. Проверь, что `STUB_ID` в окружении непустой. Если он пуст — публикация в этой сессии невозможна, и дело не в проекте.
3. Попробуй порт из `BIND_PORT`, если запускал на другом.
4. Если не вышло — скажи пользователю прямо: приложение работает, публикация недоступна по такой-то причине. Приведи вывод `/api/health` как доказательство. **Не подсовывай вместо этого `localhost`-ссылку** — пользователь не на этом хосте, для него она бесполезна.

### 6. Что не делать

- Не поднимать вместо сервера статику из `public/`. Без API страницы пустые: портфель, риски и агент рисуются из `/api/*`.
- Не выставлять дашборд наружу без пароля, если у него нет `DASHBOARD_PASSWORD`. Публичная ссылка без пароля открывает портфель, запуск агента и настройки Telegram любому, кто её получит. Пароль задаётся переменной окружения, генерировать самому не надо — спроси пользователя.
- Не отдавать файлы через `expose`: он для живых портов.
- Не придумывать, что дашборд работает, если health не ответил.

## Что должно получиться

Публичная ссылка, по которой открываются три страницы: «Портфель», «Рейтинг риска» и «Агент». Портфель изначально пустой — токены добавляются в интерфейсе кнопкой «＋ Мои токены», либо есть кнопка демо-портфеля.

Ключи для запуска не нужны. Telegram и ключ ASCN Crypto API — опционально, вводятся в интерфейсе на странице «Агент», и нужны только для сводок и ИИ-разбора.
